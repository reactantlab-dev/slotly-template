## Commands

```bash
npm run dev                              # creates + seeds data/slotly.db if missing, starts on :3000
npm test                                 # grading suites for the ticket in the branch name
npm test -- --ticket SLOT-102            # same, explicit ticket
npm run typecheck
npm run db:generate -- --name=<change>   # migration from lib/db/schema.ts → drizzle/NNNN_<change>.sql
npm run db:migrate                       # apply migrations to the local db
npm run db:reset                         # wipe local db, migrate, seed
```

Never use `drizzle-kit push`: CI builds the database from the migrations in `drizzle/`, so every schema change needs a generated, committed migration. Never edit a migration that is already on `main`.

## Drizzle (0.45.4 with better-sqlite3)

**Warning:** the Drizzle website and many examples now show **v1.0 RC** APIs. In this project, do **not** use: `defineRelations` / relations v2, `drizzle-orm@rc`, `await migrate(db)` without a config, `getColumns`, the `casing` rework, per-folder migrations. If an example does not compile here, it is probably v1 syntax.

Connection (already in `lib/db/index.ts` — import `db` from `@/lib/db`, do not create new connections):

```ts
import Database from "better-sqlite3";
import { drizzle } from "drizzle-orm/better-sqlite3";
const db = drizzle({ client: new Database("data/slotly.db"), schema });
```

Schema uses snake_case column names and camelCase TypeScript keys. Return constraints as an array from the third sqliteTable argument.

Queries are synchronous. Finish with `.all()` (array), `.get()` (one row or undefined), or `.run()` (write).

```ts
import { eq } from "drizzle-orm";

const service = db.select().from(services).where(eq(services.id, id)).get();
const created = db.insert(services).values(newService).returning().get();
db.update(services).set({ description }).where(eq(services.id, id)).run();
```

Transactions with better-sqlite3 must be synchronous. An async callback throws "Transaction function cannot return a promise".

```ts
const service = db.transaction((tx) => {
  const created = tx.insert(services).values(newService).returning().get();
  tx.update(services).set({ description }).where(eq(services.id, created.id)).run();
  return created;
});
```

## Next.js route handler pattern

```ts
// app/api/things/[id]/route.ts
import { NextResponse, type NextRequest } from "next/server";
import { z } from "zod";
import { jsonError } from "@/lib/http";

const Params = z.object({ id: z.coerce.number().int().positive() });

export async function GET(_request: NextRequest, { params }: { params: Promise<{ id: string }> }) {
  const parsed = Params.safeParse(await params);
  if (!parsed.success) return jsonError(400, "validation_error", "Invalid id");
  const thing = findThing(parsed.data.id); // from lib/
  if (!thing) return jsonError(404, "not_found", "Thing not found");
  return NextResponse.json({ thing });
}
```

## Auth (Better Auth)

- Instance: `lib/auth.ts`. Handler: `app/api/auth/[...all]/route.ts`. Schema: `lib/db/auth-schema.ts` (generated by `npx auth@1.7.25 generate --config lib/auth.ts --output lib/db/auth-schema.ts`; then `npm run db:generate`).
- Session on the server: `const session = await auth.api.getSession({ headers: await headers() })` (`headers` from `next/headers`). `null` when signed out.
- Client: `createAuthClient` from `better-auth/react`.
- Keep `nextCookies()` as the **last** plugin.

## Project rules

- Follow `docs/` exactly: endpoint paths, JSON shapes, status and error codes, UI copy, roles and labels. Tests are written against the spec.
- `tests/` already contains the tests of every ticket — they are the executable spec. Tests of later tickets fail until those tickets are done; `npm test` runs only the current ticket's suite and earlier ones.
- **Never modify** `tests/`, `vitest.config.ts`, `playwright.config.ts`, `scripts/grade.mjs`, `.github/`, `package.json`, `package-lock.json`. If a test looks wrong, say so — do not change it.
- "Now" comes only from `now()` in `lib/clock.ts`. All times UTC.
- Business logic in `lib/`; route handlers stay thin; UI uses `components/ui` (`Button`, `ButtonLink`, `Field`, `Input`, `Alert`, `Badge`, `Surface`, `PageHeader`, `EmptyState`).
- Errors: `jsonError(status, code, message)` with codes from `docs/api.md`.
- English for UI text, messages, code, comments and commits. No secrets in code; `.env*` is git-ignored.
- Keep the diff to the ticket. Do not reformat or refactor unrelated files.
